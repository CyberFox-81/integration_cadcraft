## Embedding bridge

Started with `?host=parent` inside an iframe, CADCraft talks to its parent window with `postMessage`. It only accepts messages from the parent window on its own origin, and only sends to that origin. Every message is a plain object with a `type`:

| Message | Direction | Fields | Meaning |
|---|---|---|---|
| `cadcraft:ready` | CADCraft → parent | `version` | The app is listening; send a file now. |
| `cadcraft:open` | parent → CADCraft | `name`, `bytes` (`ArrayBuffer` or `Uint8Array`) | Open this file, as File › Open would. |
| `cadcraft:save` | CADCraft → parent | `name`, `bytes` (transferred `ArrayBuffer`) | A file CADCraft would otherwise download: Save, Save As or Export. `name` is a file name, or a path the parent picked. The parent stores the file and reports success or failure itself. |
| `cadcraft:dirty` | CADCraft → parent | `dirty` (boolean) | Unsaved changes appeared or went away. |
| `cadcraft:failed` | CADCraft → parent | `error` | The app couldn't start (for example, no WebGPU or WebGL2). |

With `?host=parent`, CADCraft starts on the Start tab rather than an empty Drawing1, the files it saves go to the parent instead of the browser's downloads (the engine's delivery hook), and the parent guards leaving the page with unsaved changes.

Without `?host=parent`, CADCraft behaves exactly as upstream: saved files download.
